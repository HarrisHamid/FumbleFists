## What this is

FumbleFists — a "swipe to spar" app: students who failed an exam match with each other for a consensual sparring bout. Built on Lovable's TanStack Start template (React 19, TypeScript, Tailwind v4, shadcn/ui). There is no backend or database; all persistence is `localStorage`.

## Commands

Bun is the package manager (`bun.lock`); npm also works.

```bash
bun install
bun run dev        # vite dev server (tries port 8080, falls back to next free port)
bun run build      # production build via nitro (Cloudflare target) → .output/
bun run preview
bun run lint       # eslint .
bun run format     # prettier --write .
```

There is no test framework configured. `bun run build` is the fastest full type/bundle check.

## Architecture

- **Routing** is file-based in `src/routes/` (see `src/routes/README.md` for filename → URL conventions). `src/routeTree.gen.ts` is generated by the dev server/build — never edit it by hand. `__root.tsx` is the only app shell; it provides the `QueryClient` via router context and must keep `<Outlet />`. Do not introduce Next.js/Remix conventions (`src/pages/`, `app/layout.tsx`).
- **Pages**: `/` (landing), `/profile` (create fighter profile → redirects to `/spar`), `/spar` (swipe deck of hardcoded `FIGHTERS` with images from `src/assets/`), `/history` (past matches). Each route sets its own `head()` meta.
- **State**: `src/lib/storage.ts` is the single persistence layer (`fumblefists-profile` and `fumblefists-matches` keys, matches capped at 50). Because pages are SSR'd, callers guard reads with `typeof window !== "undefined"`.
- **Server/error plumbing (template-provided, leave intact)**: `vite.config.ts` points the server entry at `src/server.ts`, which wraps TanStack's handler to turn h3-swallowed SSR errors into an HTML error page, using `lib/error-capture.ts` to recover the original stack. `src/start.ts` registers the error middleware and re-adds CSRF protection for server functions (defining `start.ts` disables the default one). `lib/lovable-error-reporting.ts` forwards client errors to Lovable's runtime.
- **Vite config**: `@lovable.dev/vite-tanstack-config` already bundles TanStack Start, React, Tailwind, tsconfig paths, the `@/` → `src/` alias, and nitro. Do not add those plugins manually — duplicates break the app. Pass extra config through `defineConfig({ vite: { ... } })`.
- **Styling**: Tailwind v4 with theme tokens in `src/styles.css` (`@theme inline`). Beyond the shadcn tokens, the app's look uses custom colors `ink`, `paper`, `cream`, `flame`, `match`, `blood` and fonts `font-display` (Bebas Neue), `font-anton`, `font-body`, loaded from Google Fonts in `__root.tsx`. `src/components/ui/` holds stock shadcn components (config in `components.json`); `src/hooks/use-mobile.tsx` backs the sidebar.

## Lovable sync

This project is connected to Lovable (see `AGENTS.md`). Commits pushed to the connected branch sync back into the Lovable editor, so keep that branch buildable, and never rewrite pushed history (force-push, rebase, amend, or squash of pushed commits) — it destroys the user's project history on Lovable's side.
